Diagnosis. Subpages and converted markdown render correctly, so the deployment of commit 0d0b1d5 is live. Only the root document is wrong: it serves the content and title of README.md ('# Vegas1'), not the index.html committed on main (whose title is 'Vegas1 - Las Vegas Vacation Planning'). The 13:32 Pages build ran at commit 9b8bcfa, when the repo held only an 8-byte README and no index.html, so Pages generated a README-based index. The later build does not appear to have replaced it at the root.

Impact. Anyone opening the URL from the repo's About link, a search result or a shared link lands on a page that says '# Vegas1' and nothing else. Every subpage works but is effectively unreachable by browsing. This is the single most user-visible defect in the project.

Fix. Trigger a fresh Pages deployment for main (push any commit to main, or use Settings > Pages > 'Re-run' / the Actions 'pages-build-deployment' re-run button) and then reload the root URL. Verify the root title reads 'Vegas1 - Las Vegas Vacation Planning'. If it persists, delete and recreate the Pages site.
